Nexus Search Architecture

Current contracts and ownership. Updated 2026-10-15.

Search runs in the owning Kernel's signed Rust plugin. The native API is nexus.search.v1.SearchService. Rust HTTP and language clients use that contract. The local acceptance checklist and recorded evidence are at Nexus Search local acceptance.

2. Rust implementation

rust/search-plugin owns VFS discovery, chunking, Tantivy keyword indexing, ANN vectors, embeddings, fusion and stream checkpoints. rust/search-common owns shared query/result contracts, discovery options, delegation and transport connections. rust/federated-search owns cross-zone dispatch and result fusion.

Glob and grep inspect current VFS paths and bytes. Indexed keyword, semantic and hybrid queries use the committed search indexes. A stale index cannot replace a current-byte grep.

Graph queries are unavailable (has_graph=false).

3. gRPC and identity

The wire contract is nexus/search/v1/search.proto. Nexus selects one VFS revision in its workspace Cargo dependencies and verifies Cargo.lock against it. scripts/gen_search_proto.py generates/checks Python bindings directly from that revision.

The host authenticates the caller using its existing bearer or certificate identity and resolves the operation context using the owning daemon's credential and ReBAC stores. Explicit invalid bearer credentials fail even alongside a valid node certificate. Zone selectors do not grant authority.

Query and discovery authorize candidates before returning paths or snippets. Glob/grep additionally obey directory traversal requirements. Indexing, administration and diagnostics require their own permissions. Revocation remains effective after warming query and Locate caches.

4. HTTP and clients

The optional Rust axum listener exposes /v2/search/*, /v2/documents/*, key and ReBAC management. It forwards Search operations through the authenticated gRPC contract. Both listeners belong to the same daemon. HTTP is an adapter for clients that use JSON.

Python SDK and MCP call typed Search RPCs through the client transport. CLI Search commands and the TUI worker use Rust HTTP. The Python SearchService facade owns no search indexes, SQL path resolution, Search permission cache or listing thread pool. Its list method calls the filesystem's existing sys_readdir, preserving pagination and zone-view behavior. Connector display paths are read through VFS.

Standalone Python browser login/password/OAuth compatibility still exists. Its scope must be settled before declaring the entire Python server retired. Production Moss/scode identities remain the identity source for their agents.

5. Federation

Peer fan-out within a zone and cross-zone federation have separate responsibilities. The plugin uses peer transport for per-zone search. The Rust federated dispatcher selects authorized zones, validates delegation, fans out and fuses results. Each destination enforces its own authorization. Authenticated connection reuse does not cache a caller's authorization result.

6. Streams and storage

DT_REG and DT_STREAM use the existing VFS read/stat contracts. Stream indexing tracks append progress and stable chunk indexes. Missing or incompatible checkpoints trigger reconstruction from current retained bytes. Restart recovery must agree with both committed keyword and vector indexes.

Credentials, grants and path-context configuration use their existing durable stores. Search index bytes and committed sequence/checkpoint metadata support recovery. Admission permits, pending counts, in-progress counters, futures and live request state stay in memory. A read-only query to an unindexed zone does not create an index directory.

7. Verification

scripts/test_search_local.py runs an isolated native daemon with TLS, ReBAC, a signed plugin, optional real ONNX embeddings and a temporary configuration database. It reuses the CLI/SDK/MCP/discovery/certificate-agent scripts and executes the TUI worker and terminal renderer. Every journey produces a log; any failure returns a nonzero status. --serve supports manual testing against the same prepared fixture.

VFS production_index_admission.rs controls a slow embedding provider across the interactive timeout boundary. It checks accepted work, cancellation, capacity, real receipts and restart queries. HTTP tests use a stalled TCP service to check Query/BatchQuery deadline mapping. Published-artifact CI combines real embeddings with the authenticated caller journeys.

8. Assembly

Search follows the data-owning Kernel. A scode cohost composes the same cluster services through nexus_cluster::run_with_services and supplies its managed-agent runtime. All linked VFS crates must resolve to one revision; mixing Kernel types or plugin ABI revisions is invalid.

Local candidate testing can patch the complete VFS dependency graph to one checkout. Such a candidate proof is recorded separately from a released scode artifact. Local verification does not authorize a production deployment.

9. Contract rules

  • Search uses the existing Kernel syscall and plugin ABI.
  • Connections own TLS and connection establishment. Request owners select operation budgets.
  • Interactive HTTP Search RPCs use an eight-second budget. Index/refresh/retry work follows the caller lifecycle and keeps admission capacity while accepted work is still running.
  • Committed index receipts report completed work. Overload, rejection, unavailable embeddings and deadline expiry remain explicit errors.
  • Indexing concurrency is controlled by native Search configuration. Python profile settings do not advertise a second concurrency value.
  • Existing Raft proposal, commit and apply contracts govern durable changes and recovery.

10. Remaining acceptance

Track completion, test assignments and evidence in the local acceptance checklist. The indexing-deadline fix, cleanup CI, actual scode/cohost local workflows and browser identity scope must be accounted for before declaring the known mainline complete. Tencent Cloud deployment is a subsequent decision requiring a concrete plan agreed with the user.
