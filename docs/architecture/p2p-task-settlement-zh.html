P2P AI 辅助微任务结算 草案 v2.0

基于 nexus-vfs 原语构建的 P2P 任务分发与结算协议，适用于 sudowork 平台。
你的 AI 副驾负责匹配、执行和结算 — 从视频剪辑到数据标注。

为什么这很重要

1. 机会

这不仅仅是一个零工平台。AI 副驾让创意工作 — 视频剪辑、内容创作 — 变得人人可及。一个配备 sudowork 剪辑技能的大学生可以在 30 分钟内制作出专业品质的短视频。以每条视频 ¥80-150 计算，有效时薪为 ¥160-300/小时 — 超过家教、外卖及中国所有其他学生兼职选项。这是 AI 辅助劳动力，在纯现金收入层面已具备竞争力，无需依赖任何 Token 杠杆。

2. 对 sudowork 现有协作网络的价值

P2P 任务结算为 sudowork 的跨组织协作网络增加了经济激励层。如今，sudowork 支持跨公司、跨领域的多 Agent 协作，但开源贡献者、自由职业专家和跨组织工作组在没有共享薪资体系的情况下协作，缺乏原生的贡献结算方式。P2P 结算将"我们可以一起工作"升级为"我们可以一起工作，并且无需信任地进行支付结算"，不断累积网络效应 — 每个新参与者既是协作伙伴，也是潜在的买家或卖家。

3. Agent 原生 vs 平台中介

传统平台（RTB、零工市场）将匹配权中心化并收取高额佣金。Agent 原生匹配有本质区别：

维度平台中介（传统）Agent 原生（sudowork）
匹配权中心化交易所决策买方和卖方 Agent 直接协商（P2P）
任务理解平台不理解任务内容Agent 拆解、验证并执行，具有完整内容访问权
验证第三方平台，可见性有限本地 Agent 在 L1 信任域内验证
卖家学习无 — 卖家是被动的广告位Agent 随时间学习卖家偏好，成为更好的代言人

卖家的 Agent 会随时间学习其偏好。不同于平台匹配中每个任务都是独立的，sudowork 会积累关于其人类用户的知识：擅长什么类型的任务、偏好的工作时间、质量模式、领域专长。这种本地学习（完全在 L1 内）意味着任务选择随使用而改善。

层级参与者信任级别设计影响
L1：我的信任域 我 ↔ 我的 sudowork 完全信任 本地运行，100% 为我的利益行事。积分是我花钱买的，AI 是我的代理人。所有机密、策略、验收逻辑都保留在本地。
L2：对等域 我的 sudowork ↔ 对方的 sudowork 零信任 对手方可能作弊。需要密码学签名、哈希承诺。每条消息都必须可验证。没有证明就没有共享状态。
L3：平台 我 ↔ sudoprivacy 服务器 有限信任 我充值了（购买积分）。服务器持有账本。我希望它是见证者/验证者，而非裁决者。它不应对我的资金拥有单方面权力。
设计原则

最小化 L3（服务器）参与。最大化 L1（本地）智能。使 L2（对等）交互可密码学验证。服务器是见证者，而非仲裁者。

2. 角色：买家 & 卖家

角色谁做什么
买家（Buyer） 发布并支付任务 定义任务、验收标准、价格。其 sudowork 协助验证。
卖家（Seller / 劳动者） 执行工作 接受任务、执行、交付。其 sudowork 协助执行并为公平支付进行代言。

两种角色在信任结构上是对称的：各自有自己的 L1 信任域，对方始终是 L2（零信任）。

3. AI 作为代理人（信任域对齐）

利益对齐原则

每个 sudowork 实例都完全与其人类用户的利益对齐。人类用真金白银购买了驱动 sudowork 的积分 — 因此 AI 和人类在经济上紧密绑定。

  • 买家的 sudowork：优化质量验证、公平定价、检测未完成的工作
  • 卖家的 sudowork：优化高效满足验收标准、为公平报酬代言、防御不合理的拒收

这种对抗式对齐是有意为之 — 它像真实市场中的买卖协商一样产生公平的结果。

AI 在各阶段的参与：

阶段买家的 AI卖家的 AI
任务发布起草清晰的需求 + 验收标准—
协商评估还价、标记风险评估可行性、建议合理定价
执行—执行工作（剪辑、标注、编码等）
交付—打包交付物、按标准预检
验证AI 按标准自动检查（人类可异步审核 — 本地偏好，非协议强制）—
争议为买家立场收集证据为卖家立场收集证据

卖家发起的合约（反向派遣）

默认流程是买家发起：买家发布任务，卖家接单。但协议同样支持卖家发起的合约，即卖家主动提案并寻找买家。

示例：公司内一位工程师发现了一个 bug，主动提案："我来修复这个认证问题，预计 2 小时，200 积分。"团队负责人的 sudowork（买家）评估提案后，还价或接受。

协议变更：合约数据结构新增一个字段：

  "initiated_by": "buyer" | "seller"

Draft 之后的一切完全相同 — 相同的状态机、协商、双重签名、预承诺和结算流程。唯一的区别是谁创建了 Draft。

适用场景：公司内部工作（主动任务提案）、开源贡献（贡献者提出修复，维护者是买家）、自由职业推销（卖家向潜在买家展示技能）。

5. 托管问题

积分存储在 sudoprivacy 的服务器上。结算必须经过服务器。问题是：服务器拥有多大的权力？

方案 A：服务器托管

方式：买家调用 server.lock(amount, contract_hash)。服务器持有积分直到 server.release() 或超时。

优点：卖家有保障 — 积分已锁定，买家无法挪用。

缺点：服务器拥有单方面释放权。买家可能攻击释放 API。服务器被攻破 = 资金被盗。违背 L3（有限信任）原则。

方案 B：双重签名结算（无服务器托管）☆ 推荐

方式：无托管。验收通过后，买家签署 release(contract_id, amount, to_seller) 消息。卖家将 (release_msg + buyer_sig + seller_sig) 提交给服务器的 transfer API。服务器验证双方签名后执行转账。

优点：服务器是签名验证者，而非决策者。无法伪造签名。无法单方面移动资金。信任需求最小化。

缺点：买家可能拒绝签名（挟持问题）。通过超时 + 信誉来缓解。

方案 B + 预承诺（见下文）。服务器作为验证者，符合 L3（有限信任）原则。

方案 B+：买家预承诺（应对低信任市场）

问题：在低端劳动力市场，信誉薄弱。买家可能拒绝签署释放（挟持问题）。当参与者没有可损失的信誉时，"超时 + 信誉"不够用。

解决方案：当双方签署合约（agreed）时，买家同时签署一份有条件释放：

  {
    "type": "conditional_release",
    "contract_id": "...",
    "amount": 500,
    "to_seller": "seller_user_id",
    "condition": "delivery_submitted AND NOT rejected_within_timeout",
    "timeout_hours": 72,
    "buyer_signature": "ed25519:..."
  }

此预签消息在合约创建时存储在服务器上。

结算路径：

  • AI 自动验收 → 买家的 AI 检查标准，签署显式释放 → 即时转账（无需等待人类）
  • AI 或人类拒收 → 必须在超时前主动拒收并附理由 → 卖家可修改
  • 72 小时无响应 → 服务器自动执行买家预签的有条件释放
  • 人类异步干预 → 人类可在超时前任何时间点介入（本地偏好，例如"超过 100 积分的合约通知我"）

关键洞察：服务器仍然不是仲裁者 — 它只执行买家已经签署的承诺。没有单方面权力。买家在合约创建时就已自我约束。

澄清：timeout_hours 值不是由服务器设定的。它来自 contract.terms.auto_accept_timeout_hours，由买卖双方在签约前协商确定。服务器仅从买家预签的有条件释放中读取超时值 — 它不做任何业务决策。

方案 C：哈希锁定转账（HTLC 启发）

方式：买家创建哈希锁定承诺："向揭示 H 原像的人支付 N 积分"。卖家交付 + 揭示原像。自动完成。

优点：原子性 — 交付和支付通过密码学关联。

缺点：仅适用于客观可验证的交付物（文件哈希）。无法处理质量验证（"标注了但质量差"）。过于复杂。

方案 D：信誉优先（MVP 兜底方案）

方式：无托管，无密码学。买家验收后通过转账 API 支付。信任来自信誉 + 签名合约历史。

优点：最简单。无需服务器改动。适用于可信社区。

缺点：无保障。仅在有社交信任时可行。

建议

从方案 B（双重签名）开始。它并不比 D 复杂多少，但提供了真正的密码学保障。服务器只需一个新端点：POST /transfer，验证双重签名。方案 D 作为不需要正式合约的社区的备选方案。

安全保障：为什么双签无需区块链也是安全的

协议使用 Ed25519 签名 + CAS 内容寻址 — 无需区块链。三层保护：

威胁保护原理
一方否认签署 不可否认性 Ed25519 签名在数学上绑定到签名者的私钥。"我没签过"可被证伪。
一方单独行动 双签要求 服务器要求 buyer_sig + seller_sig 才执行任何转账。任何一方都不能单方面动用资金。
合约/记录被篡改 CAS 哈希 所有合约和交易记录在 VFS 上 CAS 寻址。改一个字节 → 哈希变化 → 篡改可检测。
服务器伪造交易 服务器没有私钥 服务器无法伪造签名。它只能验证和执行。被攻破的服务器无法窃取资金 — 只能拒绝服务（拒绝处理，而非盗窃）。

信任假设：服务器会诚实执行有效转账（L3 有限信任）。如果服务器拒绝处理有效的双签转账，已签署的消息可作为可审计的证据 — 与银行拒绝处理电汇的追索方式相同。

中国法律效力：我们的 Ed25519 双签满足《电子签名法》第十四条"可靠电子签名"的全部四个条件（私钥为签名人专有、签署时仅签名人控制、签名可检测篡改、内容可检测篡改）。技术上有效 — 但上法庭时，举证难度高于有 CA 牌照的平台（如法大大、e签宝），后者有工信部 CA 许可证和实名认证（身份证 + 人脸识别）。我们的签名证明"这个密钥签了这条消息"，但无法直接证明"这个密钥属于张三"，需要额外举证。建议：
  • 日常微任务（¥0.30-150）：我们的双签足够。金额小 → 诉讼概率极低。签名记录 + CAS 作为证据链已够。
  • 高价值合约（¥1000+）：可选接入 CA 电子签名 API（法大大/e签宝 SaaS）作为"加强签约"模式。我们无需自己申请 CA 牌照 — 只需 API 集成。
  • 涉及现金的回购凭证：建议使用 CA 签名。现金流转增加诉讼风险；CA 签名在中国法院具有"强证明力"。

5A. 信誉系统（复用 nexus 已有实现）

Nexus 此前有完整的信誉服务（在 PR #2600 中作为死代码删除，759 行）。数学模型设计良好，可直接复用。

已有方案：贝叶斯 Beta 信誉模型

reputation_math.py（已删除，可从 git 恢复）
  • 模型：每个维度的 Beta(alpha, beta) 分布。score = alpha / (alpha + beta)。先验 Beta(1,1) = 0.5（无信息）。
  • 4 个维度：可靠性（30%）、质量（30%）、时效性（20%）、公平性（20%） — 加权合成。
  • 时间衰减：30 天半衰期的指数衰减。近期事件权重更高。
  • 置信度：对数标度 — 0 次观察 = 0.0，10 次 = 0.71，100 次 = 0.82。
  • 联邦安全：无进程本地缓存。读操作直接访问存储。

在系统中的角色：市场信号，而非结算执行

两个独立机制，解决两个不同问题
机制解决的问题性质
预承诺 + 双重签名（§5）这笔交易不会被欺诈硬保障（密码学）
信誉（§5A）下次选择可靠的对手方软信号（统计学）

信誉不参与结算逻辑。它不限制支付，不覆盖预承诺，不解决争议。它是市场上可见的仪表盘指标 — 帮助买家选择卖家、卖家选择买家。两个系统有意解耦。

双向评价：买家和卖家都被评分

维度评价卖家评价买家
可靠性（30%）按时交付，不消失按时回应交付，不消失
质量（30%）交付物满足验收标准需求清晰且合理
时效性（20%）在截止日期前完成在超时期限内验收/拒收
公平性（20%）定价合理，诚实工作不恶意拒收，不压价

买家信誉与卖家信誉同等重要 — 卖家需要在接受任务前了解买家是否值得信赖。与网约车模式相同（司机评乘客，乘客评司机）。

Agent 代表人类进行评价（L1 对齐）

Agent 代表其人类用户提交反馈。这不是自主 AI 评分 — Agent 在 L1 信任域内行事，与人类利益对齐（人类花钱购买了驱动 Agent 的积分）。

人类审核多少 vs 委托给 AI 多少是本地偏好：有些用户会审核每个评价，有些会让 AI 处理常规反馈。这个对齐过程完全在 L1 内 — 不在协议范围内。协议只要求反馈由 Agent 的密钥签名，而该密钥由人类控制。

复用 reputation_math.py 纯函数（Beta 评分 + 时间衰减 + 合成）。用 VFS JSON 替换 ORM。双向评价（买家 + 卖家）。信誉仅作为市场信号 — 不限制结算。

可携带凭证：从信誉到就业

中国每年约有 1170 万大学毕业生（2025 年），青年就业率处于历史低位。仅有 AI 技能培训还不够，学生需要可验证的证明来获得雇主认可。信誉系统恰好提供了这一点 — 防篡改、雇主可验证的工作履历。

层级标准证明了什么
AI 工作能力认证（通用） 完成 N 个任务（不限类别），综合信誉 > 阈值，持续 M 个月 此人能与 AI 工具协作产出专业品质的工作成果 — 提示词撰写、AI 辅助执行、质量验证。
领域专家认证（垂直） 在特定领域（如视频剪辑、数据标注、代码审查）完成 N 个任务，领域质量分 > 阈值 此人是 [领域] 的经过验证的从业者，拥有来自真实商业任务的量化质量指标。

为什么比传统证书更好：传统纸质证书的含义是"这个机构为此人背书"。我们的凭证则表明"此人为真实买家完成了 200 个视频剪辑任务，平均质量评分 0.92，由 CAS 地址化的任务记录验证，任何雇主都可以审计"。证明来自工作履历本身，而不是颁发机构的声誉。

完整闭环：学生获得 $100 种子 Token → 完成任务 → 赚取积分 + 学习 AI 技能 + 积累信誉 → 获得可携带凭证 → 凭证帮助找到工作。平台不仅在大学期间提供收入 — 它构建了一个可验证的职业资产，其价值超越平台本身。

社会背景：青年就业是中国当前紧迫的社会问题。一个同时提供 (a) 收入、(b) AI 技能培养、(c) 雇主认可的凭证的平台，三个维度同时回应了这一挑战。教育部合作伙伴关系将赋予制度合法性，而链上的工作履历则提供传统凭证所缺乏的实质内容。

  • 观看 ≥3 个视频（观看时长证明）

  • 行为证明：如何证明互动确实发生了？截图可以伪造。需要考虑证明机制 — 也许可以使用 sudowork 的 ai-dev-browser 的浏览器自动化日志？
  • 微任务经济性：每个任务 10 积分 = 金额很小。需要高效的合约协商（模板？）和低摩擦的结算。微支付不能有繁重的密码学流程。
场景的设计启示
  • 混合验证：协议必须支持机器可验证和人工判断的标准，并在合约中显式标注。
  • 证明类型：不同任务需要不同的证明机制 — CAS 哈希用于数据文件，截图/日志用于操作行为。协议应与证明类型无关。
  • 模板合约：低价值任务（场景 C）需要轻量级合约。基于模板的"任务类型"跳过标准任务的协商。
  • 场景决定经济模型：视频剪辑（场景 A）在纯现金层面具有竞争力。低价值场景依赖 Token 杠杆。协议相同；商业模式按场景调整。

2. 卖家的 AI 投资

卖家的 AI Token 是卖家自己的投资，而非平台成本。使用多少 AI 帮助是卖家 L1 信任域内的本地优化：

  • 高技能卖家：主要手动完成剪辑，仅使用 AI 进行字幕和格式检查（节省 Token，保留更多利润）

4. Token 经济

大学生 $100 种子 Token

通过高校合作分发：每位学生注册时获得 $100 免费 Token（约 10,000 积分）。这将启动飞轮 — 学生使用 Token 运行 sudowork 的剪辑技能，完成任务，赚取更多积分，最终成为将子任务（字幕翻译、缩略图设计）分派给其他学生的微买家。Token 在学生网络内流通，形成有机 P2P 经济。这与商业计划书中"每天 ¥100 免费 Token"策略一致，但锚定在具有明确 ROI 的特定任务类型上。

10-20x 杠杆：使用 AI vs 兑现

回购费率（原始充值价格的 5-10%）创造了10-20x 杠杆效应，自然驱动 AI 采用：

卖家选择积分价值有效价值倍率
用积分换 AI 使用（sudowork） 任务赚取 50 积分 ¥0.50 的 AI 算力 1x 面值
兑现（回购） 任务赚取 50 积分 ¥0.025-0.05 现金 0.05-0.1x 面值

经济逻辑：模型提供商补贴（如 DSV4 定价）意味着平台的实际算力成本远低于充值价格。这个成本差被作为放大的 AI 价值传递给卖家 — 50 积分购买 ¥0.50 的 AI 算力，而平台成本可能仅 ¥0.05。回购费率（¥0.025-0.05）大致匹配平台的真实成本，因此可持续。

回购机制

卖家赚取积分但需要真实货币。sudowork 以原始充值价格的 5-10% 提供稳定价格回购。

  • 表述："退款"或"信用兑换" — 而非"兑换"或"提现"（避免金融工具分类）
  • 机制：卖家发起回购请求 → sudoprivacy 按公示回购价将金额充值到卖家的支付方式
  • 费率示例：充值费率 ¥1 = 100 积分。回购费率：100 积分 = ¥0.05-0.10
  • 政策风险：需法律审查。将其表述为"未使用信用额度的部分退款"比"货币兑换"更安全。先例：Steam Wallet、Apple App Store 信用额度有类似的退款机制。

二级市场：回购凭证

Token 具有真实经济价值（模型 API、技能、SaaS）— 二级市场必然会自然形成，无论我们是否促进（与游戏币、Steam 余额等一样）。不受管控的场外交易有欺诈风险且不可见（无数据）。为将二级市场保持在我们视野范围内，同时不触碰监管边界，我们引入回购凭证：

  1. A（Token 买方）向数牍存入 ¥X → 获得价值 ¥X 的回购凭证（100% 回购，但不可用于 AI 或任何服务 — 纯粹是退款权）
  2. A 将凭证转让给 B（通过 dual-sig）↔ B 将 Token 转让给 A（通过 dual-sig）
  3. B 向数牍出示凭证 → 获得 ¥X 现金

凭证与 Token 之间的兑换比率由 A 和 B 自行协商 — 平台不设定也不建议比率。A 可能用 ¥50 凭证换 70 Token（B 用 70 Token 换回 ¥50 现金 = 71% 比率），或双方同意的任何其他比率。

设计约束要求原因
凭证不可购买 AI/服务是区别于虚拟货币 — 它是预付费退款权
凭证仅限单次转让是A → B 仅一次，不可再次流通 → 不构成可交易工具
凭证金额 = 存入金额是100% 回购，无金融衍生品特征
平台不设定兑换比率是避免"交易所"或"市场"的监管定性
所有转让由服务器记录已实现双签转账（§5）已使服务器拥有完整可见性 — 无需额外基础设施

实现效果：卖家获得比 5% 回购更好的提现比率（市场决定，预计 20-40%）。买家以面值获得 Token（无折扣）。平台对二级市场流向拥有完整可见性，同时不作为中介参与。无新增监管风险 — 凭证是预付费退款权（类似 2025 年最高法预付式消费司法解释中的 7 日无条件退款），而非虚拟货币。

监管说明：此机制在实施前需要法律审查。核心辩护点在于凭证是 (a) 无功能的（不能购买服务），(b) 不流通的（单次转让），(c) 固定价值的（100% 存入金额）。这些属性使其区别于 2026 年八部委通告中定义的虚拟货币。然而，实质重于形式原则意味着监管机构可能会审视整体资金流向（A 付现金 → B 收到现金 → Token 转移），而不仅仅看标签。

场景适配

对于场景 A（视频剪辑），纯现金收入已具备竞争力 — ¥160-300/小时超过所有学生替代方案。Token 杠杆是锦上添花，放大了本已强劲的经济模型。对于低价值场景（场景 C：抖音微任务，¥0.30-0.50/任务），Token 杠杆成为核心差异化因素 — 10-20x 的 AI 价值差距才是让这份零工值得做的原因。

6. 各任务类型的 AI 效率

AI 价值因场景而异。下表映射了 AI 在交易层（协商、验证、结算）vs 执行层（实际工作）中的价值。

任务类型交易层（AI 价值）执行层（AI 价值）备注
视频剪辑（场景 A） 高 — 自动检查格式、字幕、时长 极高 — AI 完成约 80%（模板、字幕、音乐、节奏） AI 将 2-3 小时的手动任务缩短为 30 分钟。最强经济模型。
数据标注（场景 B） 高 — 自动验证格式、抽检准确率 高 — AI 预标注，人工修正 AI 在两层都增值。成熟的应用场景。
社交互动（场景 C） 高 — 自动验证截图、评论相关性 中 — AI 起草评论，人类执行操作 执行是物理性的（App 交互）；AI 辅助但无法替代。
插画/代画 高 — 风格一致性检查、格式验证 中 — AI 辅助创意（构图、配色、参考搜索），人类手绘 现有碎片化市场（米画师、半次元约稿）。txt2img 有天花板 — 人类艺术性仍是核心价值。AI 增强，不替代。
Code Review / 架构评审 高 — 自动运行测试、lint、安全扫描 高 — AI 生成测试、发现 bug、检查模式 最高价值的脑力劳动。架构 + CR 是高级工程师创造最大差异化的地方。任务天然可拆解（按 PR、按文件）。

设计启示：协议与任务类型无关，但平台引导应将卖家导向 AI 杠杆最高的任务类型 — 最大化收入效率和 AI 技能发展。

7. 卖家专业化

在特定领域积累任务历史的卖家可以通过后训练构建信誉护城河。拥有本地 GPU（如 DGX）的卖家可以用已完成的任务数据微调模型 — 标注图片、视频剪辑模式、代码审查决策 — 随时间提升质量和速度。更高质量 → 更高信誉 → 以更高价格获得更多任务（正反馈循环）。没有 GPU 的卖家，sudowork 的模型选择元学习会记住哪种模型最适合哪种任务类型和哪位卖家，为所有人提供轻量级专业化。

8. 开放问题

  1. 托管模型：从 B（双重签名）还是 D（信誉）开始？
    从 B 开始。服务器 API 成本仅一个端点（POST /transfer，带签名验证）。单靠信誉（D）对陌生人来说太弱。B 从第一天起就提供真正的保障。
  2. 争议解决：P2P 信誉还是平台仲裁？
    v1 用 P2P 信誉。平台仲裁是 v2 功能，需要 sudoprivacy 建立仲裁团队/流程。签名合约 + 审计日志在争议升级到系统外时提供证据。
  3. 积分转账 API：sudoprivacy 是否已支持用户间转账？
    已确认：无转账 API。当前系统仅支持充值（向 sudoprivacy 付款）和消费（使用 LLM）。需要新端点：POST /api/v1/transfer，带双重签名验证。转账接口必须接受 (release_msg + buyer_sig + seller_sig)，验证双方 Ed25519 签名是否匹配合约条款，并原子性地在账户间移动积分。最小接口 — 一个新端点，无托管状态。
  4. 发现/市场：买家如何找到卖家？
    v1：KOOK 社区服务器用于发现 + 直接 P2P 用于结算。买家在 KOOK 频道发布任务需求，卖家看到后通过 sudowork 发起合约协商。KOOK 的服务器创建、消息和机器人功能免费 — 无市场佣金，无隐藏费用（VIP 仅用于语音功能如屏幕分享和 AI 降噪）。KOOK 不参与结算 — 仅作为发现渠道。演进路径：KOOK 社区 → sudowork 内置任务板（简单列表视图） → 完整市场（搜索 + 推荐 + 卖家档案）。每一步由 PMF 信号决定是否推进。风险：如果 KOOK 未来对商业用途收费，迁移成本低（飞书群/Telegram 群可直接替代）。自建市场是重大工程（搜索、档案、分类体系）— v1 阶段为时过早。
  5. 积分回购机制：卖家如何将赚取的积分转换为真实货币？
    以原始充值价格的 5-10% 稳定价格回购（见 §7A）。关键待解决事项：(a) 法律分类 — "部分退款"表述 vs "货币兑换"风险，需法律审查；(b) 回购费率稳定性 — 固定费率还是随使用指标浮动；(c) 最低门槛 — 避免处理成本超过回购金额的微额提现；(d) 频率限制 — 每日/每周上限以管理现金流。政策风险确实存在：如果监管机构将积分归类为金融工具，合规负担将显著增加。先例：Steam Wallet、Apple App Store 信用额度有类似的退款机制。
