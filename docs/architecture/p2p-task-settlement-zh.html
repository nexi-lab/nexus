P2P AI 辅助微任务结算 草案 v1.5

基于 nexus-vfs 原语构建的 P2P 任务分发与结算协议，适用于 sudowork 平台。
每位卖家都有 AI 副驾。每个任务都是学习 AI 协作的机会。

为什么这很重要

这不仅仅是一个微任务平台，而是大规模推动 AI 辅助劳动力应用的载体。

如今，AI 工具主要被知识工作者使用。大多数劳动力从未在日常工作中体验过 AI 增强。本平台改变了这一点：卖家通过完成微任务赚取收入，在此过程中，他们学会与 AI 副驾协作 — 理解任务、生成内容、生产工作证明。他们培养的技能 — 提示词编写、AI 辅助写作、工具委派 — 可以直接迁移到他们自身的职业发展中。

经济激励（赚取积分）为教育（学习 AI 辅助工作）提供资金。该平台同时解决了买家对可扩展任务完成的需求和卖家对可获得的 AI 技能培养的需求。这在社会层面意义深远：为更广泛的劳动力 — 而非仅限于技术精英 — 降低 AI 应用门槛。

对 sudowork 现有协作网络的价值

除了创造新市场，P2P 任务结算还增强了 sudowork 的核心产品理念：1% 点对点协作网络。如今，sudowork 支持跨公司、跨领域的多 Agent 协作 — 但并非所有协作都发生在企业内部。开源贡献者、非营利组织、自由职业专家和跨组织工作组都在没有共享薪资体系的情况下进行协作。这些协作缺乏经济激励层：在属于不同组织的两个 sudowork 实例之间，没有原生方式来结算代码审查、设计评审或研究贡献。

P2P 任务结算填补了这一空白。它将 sudowork 的协作网络从"我们可以一起工作"升级为"我们可以一起工作，并且无需信任地进行支付结算"。这为 1% 点对点网络创造了新的激励：每个新参与者不仅是协作伙伴，还是微任务的潜在买家或卖家。网络效应不断累积 — 更多参与者意味着更多任务流动性，从而吸引更多参与者。

Agent 原生匹配 vs 传统 RTB

在线广告使用实时竞价（RTB）：第三方交易所在约 100ms 内匹配买家和卖家。该系统适用于广告，但不适用于劳动力 — 平台控制所有匹配权力，抽取高额佣金，且不理解任务内容。Agent 原生匹配有本质区别：

维度RTB（传统）Agent 原生（sudowork）
匹配权中心化交易所（平台决策）买方和卖方 Agent 直接协商（P2P）
任务拆解不可能 — 平台不理解任务内容Agent 将复杂任务拆解为微任务（理解内容）
验证第三方平台，可见性有限本地 Agent 验证（L1 信任域，完整内容访问）
任务粒度粗粒度（一次广告展示 = 一个单位）细粒度 → 更好的流动性（Agent 可拆分/合并）
卖家学习无 — 卖家是被动的广告位Agent 通过协作教卖家 AI 技能

卖家的 Agent 会随时间学习其偏好。不同于 RTB 中每次展示都是独立的冷匹配，sudowork 会积累关于其人类用户的知识：擅长什么类型的任务、偏好的工作时间、质量模式、领域专长。这种本地学习（完全在 L1 内）意味着任务选择随使用而改善 — Agent 成为人类更好的代言人，而不仅仅是任务路由器。

层级参与者信任级别设计影响
L1：我的信任域 我 ↔ 我的 sudowork 完全信任 本地运行，100% 为我的利益行事。积分是我花钱买的，AI 是我的代理人。所有机密、策略、验收逻辑都保留在本地。
L2：对等域 我的 sudowork ↔ 对方的 sudowork 零信任 对手方可能作弊。需要密码学签名、哈希承诺。每条消息都必须可验证。没有证明就没有共享状态。
L3：平台 我 ↔ sudoprivacy 服务器 有限信任 我充值了（购买积分）。服务器持有账本。我希望它是见证者/验证者，而非裁决者。它不应对我的资金拥有单方面权力。
设计原则

最小化 L3（服务器）参与。最大化 L1（本地）智能。使 L2（对等）交互可密码学验证。服务器是见证者，而非仲裁者。

2. 角色：买家 & 卖家

角色谁做什么
买家（Buyer） 发布并支付任务 定义任务、验收标准、价格。其 sudowork 协助验证。
卖家（Seller / 劳动者） 执行工作 接受任务、执行、交付。其 sudowork 协助执行并为公平支付进行代言。

两种角色在信任结构上是对称的：各自有自己的 L1 信任域，对方始终是 L2（零信任）。

3. AI 作为代理人（信任域对齐）

利益对齐原则

每个 sudowork 实例都完全与其人类用户的利益对齐。人类用真金白银购买了驱动 sudowork 的积分 — 因此 AI 和人类在经济上紧密绑定。

  • 买家的 sudowork：优化质量验证、公平定价、检测未完成的工作
  • 卖家的 sudowork：优化高效满足验收标准、为公平报酬代言、防御不合理的拒收

这种对抗式对齐是有意为之 — 它像真实市场中的买卖协商一样产生公平的结果。

AI 在各阶段的参与：

阶段买家的 AI卖家的 AI
任务发布起草清晰的需求 + 验收标准—
协商评估还价、标记风险评估可行性、建议合理定价
执行—执行工作（标注、浏览、编码等）
交付—打包交付物、按标准预检
验证AI 按标准自动检查（人类可异步审核 — 本地偏好，非协议强制）—
争议为买家立场收集证据为卖家立场收集证据

5. 托管问题

积分存储在 sudoprivacy 的服务器上。结算必须经过服务器。问题是：服务器拥有多大的权力？

方案 A：服务器托管

方式：买家调用 server.lock(amount, contract_hash)。服务器持有积分直到 server.release() 或超时。

优点：卖家有保障 — 积分已锁定，买家无法挪用。

缺点：服务器拥有单方面释放权。买家可能攻击释放 API。服务器被攻破 = 资金被盗。违背 L3（有限信任）原则。

方案 B：双重签名结算（无服务器托管）☆ 推荐

方式：无托管。验收通过后，买家签署 release(contract_id, amount, to_seller) 消息。卖家将 (release_msg + buyer_sig + seller_sig) 提交给服务器的 transfer API。服务器验证双方签名后执行转账。

优点：服务器是签名验证者，而非决策者。无法伪造签名。无法单方面移动资金。信任需求最小化。

缺点：买家可能拒绝签名（挟持问题）。通过超时 + 信誉来缓解。

方案 B + 预承诺（见下文）。服务器作为验证者，符合 L3（有限信任）原则。

方案 B+：买家预承诺（应对低信任市场）

问题：在低端劳动力市场，信誉薄弱。买家可能拒绝签署释放（挟持问题）。当参与者没有可损失的信誉时，"超时 + 信誉"不够用。

解决方案：当双方签署合约（agreed）时，买家同时签署一份有条件释放：

  {
    "type": "conditional_release",
    "contract_id": "...",
    "amount": 500,
    "to_seller": "seller_user_id",
    "condition": "delivery_submitted AND NOT rejected_within_timeout",
    "timeout_hours": 72,
    "buyer_signature": "ed25519:..."
  }

此预签消息在合约创建时存储在服务器上。

结算路径：

  • AI 自动验收 → 买家的 AI 检查标准，签署显式释放 → 即时转账（无需等待人类）
  • AI 或人类拒收 → 必须在超时前主动拒收并附理由 → 卖家可修改
  • 72 小时无响应 → 服务器自动执行买家预签的有条件释放
  • 人类异步干预 → 人类可在超时前任何时间点介入（本地偏好，例如"超过 100 积分的合约通知我"）

关键洞察：服务器仍然不是仲裁者 — 它只执行买家已经签署的承诺。没有单方面权力。买家在合约创建时就已自我约束。

澄清：timeout_hours 值不是由服务器设定的。它来自 contract.terms.auto_accept_timeout_hours，由买卖双方在签约前协商确定。服务器仅从买家预签的有条件释放中读取超时值 — 它不做任何业务决策。

方案 C：哈希锁定转账（HTLC 启发）

方式：买家创建哈希锁定承诺："向揭示 H 原像的人支付 N 积分"。卖家交付 + 揭示原像。自动完成。

优点：原子性 — 交付和支付通过密码学关联。

缺点：仅适用于客观可验证的交付物（文件哈希）。无法处理质量验证（"标注了但质量差"）。过于复杂。

方案 D：信誉优先（MVP 兜底方案）

方式：无托管，无密码学。买家验收后通过转账 API 支付。信任来自信誉 + 签名合约历史。

优点：最简单。无需服务器改动。适用于可信社区。

缺点：无保障。仅在有社交信任时可行。

建议

从方案 B（双重签名）开始。它并不比 D 复杂多少，但提供了真正的密码学保障。服务器只需一个新端点：POST /transfer，验证双重签名。方案 D 作为不需要正式合约的社区的备选方案。

5A. 信誉系统（复用 nexus 已有实现）

Nexus 此前有完整的信誉服务（在 PR #2600 中作为死代码删除，759 行）。数学模型设计良好，可直接复用。

已有方案：贝叶斯 Beta 信誉模型

reputation_math.py（已删除，可从 git 恢复）
  • 模型：每个维度的 Beta(alpha, beta) 分布。score = alpha / (alpha + beta)。先验 Beta(1,1) = 0.5（无信息）。
  • 4 个维度：可靠性（30%）、质量（30%）、时效性（20%）、公平性（20%） — 加权合成。
  • 时间衰减：30 天半衰期的指数衰减。近期事件权重更高。
  • 置信度：对数标度 — 0 次观察 = 0.0，10 次 = 0.71，100 次 = 0.82。
  • 联邦安全：无进程本地缓存。读操作直接访问存储。

在系统中的角色：市场信号，而非结算执行

两个独立机制，解决两个不同问题
机制解决的问题性质
预承诺 + 双重签名（§5）这笔交易不会被欺诈硬保障（密码学）
信誉（§5A）下次选择可靠的对手方软信号（统计学）

信誉不参与结算逻辑。它不限制支付，不覆盖预承诺，不解决争议。它是市场上可见的仪表盘指标 — 帮助买家选择卖家、卖家选择买家。两个系统有意解耦。

双向评价：买家和卖家都被评分

维度评价卖家评价买家
可靠性（30%）按时交付，不消失按时回应交付，不消失
质量（30%）交付物满足验收标准需求清晰且合理
时效性（20%）在截止日期前完成在超时期限内验收/拒收
公平性（20%）定价合理，诚实工作不恶意拒收，不压价

买家信誉与卖家信誉同等重要 — 卖家需要在接受任务前了解买家是否值得信赖。与网约车模式相同（司机评乘客，乘客评司机）。

Agent 代表人类进行评价（L1 对齐）

Agent 代表其人类用户提交反馈。这不是自主 AI 评分 — Agent 在 L1 信任域内行事，与人类利益对齐（人类花钱购买了驱动 Agent 的积分）。

人类审核多少 vs 委托给 AI 多少是本地偏好：有些用户会审核每个评价，有些会让 AI 处理常规反馈。这个对齐过程完全在 L1 内 — 不在协议范围内。协议只要求反馈由 Agent 的密钥签名，而该密钥由人类控制。

复用 reputation_math.py 纯函数（Beta 评分 + 时间衰减 + 合成）。用 VFS JSON 替换 ORM。双向评价（买家 + 卖家）。信誉仅作为市场信号 — 不限制结算。

7. 场景

三个场景按战略优先级排序。场景 A 是推荐的上线场景。

场景 A：跨境电商视频剪辑

买家：跨境电商品牌（中国工厂/品牌方）需要为 TikTok Shop、Amazon 等平台制作短视频。"将原始素材剪辑成 30 秒的产品视频，带字幕、转场和音乐。每条视频 ¥80-150。"

卖家：具备基础剪辑技能的大学生。其 sudowork 提供视频剪辑技能（来自技能商店），处理模板选择、自动字幕、音乐匹配和格式合规。学生负责审核和调整创意选择。

验收标准：

  • 视频时长符合规格（机器可验证）
  • 平台格式正确 — 宽高比、分辨率、文件大小（机器可验证）
  • 字幕存在且准确（AI 可验证）
  • 创意质量 — 节奏、转场、品牌调性（AI 辅助，买家审核）

交付：剪辑后的视频文件 + 工程文件存入 VFS。CAS 哈希覆盖两者。

Token 流通：$100 种子模型

通过高校合作进行分发：

  1. 学生注册时获得 $100 免费 Token（约 10,000 积分）
  2. 使用 Token 运行 sudowork 的剪辑技能 → 完成剪辑任务 → 赚取更多积分
  3. 赚取的积分用于更多 AI 使用 → 自循环飞轮
  4. 高积分学生成为微买家 — 使用赚取的积分将子任务（如字幕翻译、缩略图设计）分派给其他学生
  5. Token 在学生网络内流通 → 有机 P2P 经济

这与商业计划书中"每天 ¥100 免费 Token"策略一致，但锚定在具有明确 ROI 的特定任务类型上。

跨境买家供给

合作平台（如跨境电商 SaaS 服务商）提供买家侧 — 即已有大规模视频剪辑需求的品牌。合作方为其用户白标集成 sudowork，提供现成的买家池。我们的角色：结算协议 + AI 剪辑能力。合作方的角色：买家获取 + 品牌关系。

压力测试：

  • 质量差异：视频剪辑比数据标注更主观。买家的 AI 可以检查格式/时长/字幕，但创意质量需要人工审核。缓解措施：信誉系统（质量维度）+ 卖家随时间专业化。
  • 技能依赖：价值主张依赖于 sudowork 剪辑技能的真正优秀。如果 AI 剪辑质量差，学生无法产出可接受的成果，飞轮就会崩溃。产品必须在此处兑现。
  • 为什么选学生而非 Fiverr 自由职业者？：(a) Token 杠杆 — 学生获得 10-20x AI 价值，Fiverr 自由职业者只拿现金。(b) sudowork 处理难的部分（剪辑），学生处理简单的部分（创意审核）。(c) 校园分发 = 低 CAC。

场景 B：数据标注（使用真实生产数据）

买家："标注 1000 张图片用于目标检测。COCO 格式的边界框。500 积分。"

卖家：数据标注员。其 sudowork 运行标注流水线（模型选择、检测、分类），卖家负责质量审核。

验收标准：

  • 全部 1000 张图片已标注（数量检查 — 机器可验证）
  • COCO JSON 格式有效（格式检查 — 机器可验证）
  • 50 张图片抽检准确率 > 95%（质量检查 — AI 辅助，人工确认）

交付：COCO JSON + 标注图片存入 VFS。CAS 哈希覆盖整个数据集。

  • 流水线作为产品能力：卖家不需要自己搭建流水线。sudowork 将 OmniParser + 模型编排作为产品级能力提供。卖家说"标注这些图片"，sudowork 处理其余工作。sudowork 产品团队必须为关键任务类型持续提升流水线能力。
  • 卖家专业化：完成大量标注任务的卖家可以在本地 GPU（如 DGX）上用积累的任务数据微调本地模型，随时间提升准确率 → 更高信誉 → 以更高价格获得更多任务（正反馈循环）。没有 GPU 的卖家，sudowork 的模型选择元学习会记住哪种模型最适合哪种任务类型 — 为所有卖家提供轻量级专业化。
  • 部分质量：如果 900/1000 质量好但 100 质量差怎么办？要求修改还是部分支付？

场景 C：社交媒体互动（抖音）

买家：品牌/创作者希望获得自然互动。"访问我的抖音主页，浏览 3+ 个视频，感兴趣则关注，点赞 1-2 个视频，留下一条真实评论。10 积分。"

卖家：拥有抖音账号的真人。其 sudowork 引导他们完成任务。

验收标准：

  • 主页已访问（截图或交互证明）
  • 观看 ≥3 个视频（观看时长证明）
  • 完成关注操作（粉丝数变化或截图）
  • 点赞 1-2 个视频
  • 留下 1 条真实评论（非垃圾信息，与内容相关）

交付：交互证明包（截图、时间戳）存入 VFS。

压力测试：

  • 不可逆性：不同于代码，卖家无法轻易"取消关注"。工作有现实世界的副作用。即使卖家后来失去兴趣，关注/点赞大概率会保留 — 买家获得长期价值。
  • 行为证明：如何证明互动确实发生了？截图可以伪造。需要考虑证明机制 — 也许可以使用 sudowork 的 ai-dev-browser 的浏览器自动化日志？
  • 真实性：评论必须"真实" — 这本质上是主观的。买家的 AI 可以检查评论是否与视频内容相关，但最终需要人类判断。
  • 利益对齐：如果卖家真的对内容感兴趣，他们会成为长期粉丝（双赢）。如果不感兴趣，他们仍然完成了任务但不会继续互动。两种结果都可接受 — 买家支付的是初始曝光，不是永久承诺。
  • 微任务经济性：每个任务 10 积分 = 金额很小。需要高效的合约协商（模板？）和低摩擦的结算。微支付不能有繁重的密码学流程。
场景的设计启示
  • 混合验证：协议必须支持机器可验证和人工判断的标准，并在合约中显式标注。
  • 证明类型：不同任务需要不同的证明机制 — CAS 哈希用于数据文件，截图/日志用于操作行为。协议应与证明类型无关。
  • 微任务支持：场景 C（10 积分）需要轻量级合约。也许可以基于模板的"任务类型"来跳过标准任务的协商。
  • 非数字副作用：某些交付物（社交互动）具有超出合约存续期的现实世界影响。有趣但不是协议层面的关注点。

AI 辅助：卖家的投资决策

卖家的 AI Token 是卖家自己的投资，而非平台成本。使用多少 AI 帮助是卖家 L1 信任域内的本地优化：

  • 高技能卖家：主要手动完成，AI 使用最少（节省 Token，保留更多利润）
  • 低技能卖家：大量依赖 AI 指导（消耗更多 Token，但能完成原本无法完成的任务）
  • 模型选择：每个卖家自己选择模型。简单任务 → DSV4 或类似的低成本模型。协议不强制指定模型。

这创造了一个AI 辅助劳动力的自然市场：平台使 AI 辅助对微工作变得可及且经济可行，推动采用。

积分流动性：稳定价格回购

卖家赚取积分但需要真实货币。sudowork 以原始充值价格的 5-10% 提供稳定价格回购。

  • 表述："退款"或"信用兑换" — 而非"兑换"或"提现"（避免金融工具分类）
  • 机制：卖家发起回购请求 → sudoprivacy 按公示回购价将金额充值到卖家的支付方式
  • 费率示例：充值费率 ¥1 = 100 积分。回购费率：100 积分 = ¥0.05-0.10
  • 政策风险：需法律审查。将其表述为"未使用信用额度的部分退款"比"货币兑换"更安全。许多游戏平台（Steam、Apple）有类似的信用退款机制。

积分杠杆：10-20x 价值放大

为什么 Token 对卖家的价值高于现金

回购费率（5-10%）创造了10-20x 杠杆效应，自然驱动 AI 采用：

卖家选择积分价值有效价值倍率
用积分换 AI 使用（sudowork） 任务赚取 50 积分 ¥0.50 的 AI 算力 1x 面值
兑现（回购） 任务赚取 50 积分 ¥0.025-0.05 现金 0.05-0.1x 面值

经济逻辑：模型提供商补贴（如 DSV4 定价）意味着平台的实际算力成本远低于充值价格。这个成本差被作为放大的 AI 价值传递给卖家 — 50 积分购买 ¥0.50 的 AI 算力，而平台成本可能仅 ¥0.05。回购费率（¥0.025-0.05）大致匹配平台的真实成本，因此可持续。

飞轮：用积分换 AI 的卖家获得比兑现高 10-20 倍的价值 → 他们学会 AI 技能 → 发现 AI 对自身工作的价值 → 自己购买积分 → 有机增长。经济激励和教育使命是同一机制。

关键假设：这种杠杆只有在 AI 对卖家真正有用时才成立。如果卖家在 AI 辅助工作中找不到价值，他们会想兑现（但得到很少）。平台必须确保 sudowork 在卖家的 L1 信任域内提供真实价值 — 任务理解、技能发展、可迁移的 AI 素养。

    从 B 开始。服务器 API 成本仅一个端点（POST /transfer，带签名验证）。单靠信誉（D）对陌生人来说太弱。B 从第一天起就提供真正的保障。
  2. 争议解决：P2P 信誉还是平台仲裁？
    v1 用 P2P 信誉。平台仲裁是 v2 功能，需要 sudoprivacy 建立仲裁团队/流程。签名合约 + 审计日志在争议升级到系统外时提供证据。
  3. 积分转账 API：sudoprivacy 是否已支持用户间转账？
    已确认：无转账 API。当前系统仅支持充值（向 sudoprivacy 付款）和消费（使用 LLM）。需要新端点：POST /api/v1/transfer，带双重签名验证。转账接口必须接受 (release_msg + buyer_sig + seller_sig)，验证双方 Ed25519 签名是否匹配合约条款，并原子性地在账户间移动积分。最小接口 — 一个新端点，无托管状态。
  4. 发现/市场：买家如何找到卖家？
    v1 直接 P2P（买家向已知卖家发送合约邀约）。市场是 v2 功能。已确认：nexus 中无市场代码（已查 git 历史）。需从零构建 — 任务列表、搜索、卖家档案、分类体系。这是一个重要的构建工作，与结算协议分开。
  5. 部分交付/里程碑付款：拆分大型任务？
    v2。v1 中一个合约 = 一个交付物 = 一次付款。大型任务可手动拆分为多个合约。里程碑支持增加了复杂性（部分签名、部分释放），MVP 不需要。
  6. 跨平台：卖家使用非 sudowork 工具（浏览器、抖音 App、标注工具）？
    不是"双方都必须使用 sudowork" — 而是通过 MCP 服务器和 ai-dev-browser 将外部任务工具集成到 sudowork 中。卖家的 sudowork 负责编排：驱动浏览器进行抖音交互，启动标注工具，截取截图 — 所有操作都在卖家的 L1 信任域内。协议仍然要求 sudowork 到 sudowork 的通信（L2），但执行工具是可扩展的。MCP 使其即插即用：每种新工具类型只是一个新的 MCP 服务器，无需协议变更。
  7. 积分回购机制：卖家如何将赚取的积分转换为真实货币？
    以原始充值价格的 5-10% 稳定价格回购（见 §7A）。关键待解决事项：(a) 法律分类 — "部分退款"表述 vs "货币兑换"风险，需法律审查；(b) 回购费率稳定性 — 固定费率还是随使用指标浮动；(c) 最低门槛 — 避免处理成本超过回购金额的微额提现；(d) 频率限制 — 每日/每周上限以管理现金流。政策风险确实存在：如果监管机构将积分归类为金融工具，合规负担将显著增加。先例：Steam Wallet、Apple App Store 信用额度有类似的退款机制。
